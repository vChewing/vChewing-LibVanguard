## 要解決的問題

狂拼（Furious Typing，`kFuriousTypingEnabled`，預設啟用）模式啟用時，來自原廠辭典（Vanguard TextMapTrie，type 10 zhuyinwen）的注音文資料仍會混入 LM 供應的候選之中。希望狂拼啟用時將這批原廠注音文抑制掉——語意上狂拼模式的注拼槽輸入不應再被「ㄋㄟㄋㄟ」這類注音文候選干擾。

## 手術內容（兩倉鏡像，hunk 語義一致）

注音文在原廠路徑的供應只有單一匯流點：`makeFactoryUnigrams` 的兩個 overload（entries 版與 queriedGrams 版）涵蓋 configured／partial／chopped／strictSuperset 全部查詢路徑，故在此加 guard 即可全線生效，比照既有 kana 抑制（`suppressFactoryUnigramsOfKanaSyllables`）的既有模式：

1. `LMInstantiator.swift`：`Config` 新增 `public var shouldSuppressFactoryZhuyinwenData = false`（附 one-line 註解：「隨狂拼主開關（kFuriousTypingEnabled）同步」）；`syncPrefs()` 接線 `config.shouldSuppressFactoryZhuyinwenData = prefs.furiousTypingEnabled && prefs.pinyinTypingEnabled`——**狂拼與拼音打字模式皆啟用時才抑制**。
2. `LMInstantiator_TextMapExtension.swift`：兩 overload 的 kana guard 之後各加
   `if entryType == .zhuyinwen, config.shouldSuppressFactoryZhuyinwenData { continue }`（同款 one-line 註解）。
3. 語意：僅抑制**原廠 TextMapTrie 的注音文**；使用者片語／符號等其它來源不受影響；`kFuriousTypingEnabled` 關閉時維持原狀。zhuyinwen 不存在於 `hasUnigramsFor` 的存在性查詢路徑，故無需 kana 那般的特判。

## 要解決的問題（客訴）

## 根因（實機探針＋程式盤點）

- 確認 **v4.7.3 已含 P182／P183 全部**（`LMInstantiator.swift` 於 tag 與工作樹 diff 為空）：
  引擎 n-gram 餵入（`unigramsFor` 兩路徑）以 `kFetchSuggestionsFromPerceptionOverrideModel`
  （預設 on）為閘、僅餵 contextual 記憶。
- 故障機制：引擎注入呼叫 `perceptionsFor`（未指定 matchMode）→ 預設 **`.toneInsensitivePrefix`
  （逐段去聲調等值）**。具體帶調查詢（「有」ㄧㄡˇ、「時」ㄕˊ…）會因此撈回**同音異調**記憶
  （「右」ㄧㄡˋ、「式」ㄕˋ…）；注入 gram 的 keyArray＝記憶自身讀音（ㄧㄡˋ／ㄕˋ），與查詢節點
  鍵（ㄧㄡˇ／ㄕˊ）不符，但 Homa Node/DP 仍可能以 reading-mismatch 選中（fresh 記憶權重 ≈−0.17
  遠高於詞典）→ 組句／首候選出現錯調字詞（「右」；前一音節「體」＋「式」→「體式」）。
  清空 POM 即癒、與客訴完全吻合。
- 範圍收斂：此為**引擎注入層**的錯；Typewriter 建議查詢的容錯語義（狂拼 `.toneInsensitivePrefix`）
  屬另一層、不動；且**不得妨礙拼音／狂拼模式之 partial matching**（事主明示）。

## 手術內容

`LXPerceptor.perceptionsFor`（兩倉 `SubLMs/LXPerceptor.swift`）head 讀音比對規則調整：

- 預設 `matchMode` 由 `.toneInsensitivePrefix` 改為 **`.exact`**；
- `.exact` 語義改為「**逐段依 query 段是否帶聲調**」：
  - query 段**帶聲調**（具體讀音，如 ㄧㄡˇ／ㄕˊ）→ 需與記憶**逐字等值**（跨聲調記憶不注入）；
  - query 段**無聲調**（聲調桶代表鍵／前綴 partial）→ 維持**去聲調等值**容錯
    （狂拼聲調桶與拼音 partial matching 依賴此行為——IH507 為此之守衛）；
- `.toneInsensitivePrefix`（狂拼 Typewriter 建議查詢）維持全局去聲調等值、不變。
- 兩倉鏡像逐字節一致。
