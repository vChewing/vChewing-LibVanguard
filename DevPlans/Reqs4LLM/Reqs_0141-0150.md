### 調查結論

- 四個 Swift 倉的 Tekkon 模組逐字節一致（僅一行換行差異），確認可以單一正本、三處鏡像；以 vChewing-macOS 為正本。
- `has(string:)` / `swapping(_:with:)` 仍是 Phase 139 之前的舊實作（Phase 139 已註明「Tekkon 版同型最佳化留待後續 phase」，本 Phase 即該續作）：每次呼叫各配置 2 個 `Array(unicodeScalars)`，且逐索引配置視窗切片陣列；`swapping` 另對每段緩衝 `buffer.map { String($0) }.joined()`、並以 `[String]` 累積後再 `joined()`。
- 其餘 heap churn 候選點：
  - `cnvPhonaToHanyuPinyin`：逐位置、逐候選長度具體化一次性 `String` 查表鍵（每個輸入字元最多 `maxLen` 次配置）。
  - `cnvHanyuPinyinToPhona`：每次呼叫對 `mapHanyuPinyin.keys` 重新排序（一次性陣列＋排序）。
  - `isNotAllowedCharOfPinyinChain`（String / Character 兩變體）：`map(\.value).filter` 雙一次性陣列。
  - `restoreToneOneInPhona`：`String(target.reversed()[0])` 一次性字串，且空字串會崩潰（C# 版早有防呆）。
  - `pinyinAutoChopResult`：`Array(chopped.dropLast())` 一次性陣列（直接用切片即可）。
- TekkonNT（C#）同型問題：`CnvPhonaToHanyuPinyin` 逐次 `Substring` 查表鍵；`CnvHanyuPinyinToPhona` 每次呼叫 `OrderBy(...).Reverse()` 重新排序、逐次 `Rune.ToString()` / `new Rune('1')`、並以 `Regex.IsMatch` 做字元白名單檢查。
- TekkonCC（C++）同型問題：`cnvPhonaToHanyuPinyin` 逐位置逐長度拼裝一次性 `std::string` 查表鍵；`cnvHanyuPinyinToPhona` 每次呼叫重建並重排兩份鍵陣列、以 `std::regex` 做字元白名單檢查；`cnvHanyuPinyinToTextBookStyle` 迴圈逐列拷貝 `std::vector`；`replaceOccurrences` / `stringInclusion` / `contains` 等工具的 by-value 參數造成逐次呼叫拷貝；`restoreToneOneInPhona` 對空字串會回傳 `"1"`（Swift / C# 版均有防呆）。另有既有包裝缺陷：`Sources/Tekkon/Tekkon.cc`（header-only 函式庫的 dummy translation unit）內含無用的 `int main` stub，與 XCTest target 的 `_main` 產生重複符號、XCTest 套件因此無法建置。
- 檢討後不施工項：`PinyinTrie.chop` 的逐前綴 `String(givenCharComplex[range])` 具體化——屬拼音簡拼分析路徑（非逐鍵熱路徑），演算法本身需反覆前綴比對，收益邊際；`cnvHanyuPinyinToTextbookStyle` 的逐對全串替換為對照表語義所需，隨 `swapping` 零配置化已連帶受益。

### 變更（Swift 四倉同一正本）

`Tekkon_Utilities.swift`：

- `has(string:)`：套用 Phase 139 的純 Unicode Scalar view 滑窗掃描（零配置），實作逐字節對齊 Homa 版。
- `has(scalar:)`：改為 `unicodeScalars.contains(target)`，不再經 `String(Character(...))` 中轉。
- `swapping(_:with:)`：改為單趟索引走訪——命中窗口即附加替換內容並整段跳過（`index(_:offsetBy:limitedBy:)`＋`elementsEqual` 純檢視比對），不再配置任何一次性陣列。
  - ⚠️ 語義差異記錄：舊實作的 `sleepCount` 僅抑制緩衝附加、不抑制比對，目標自體重疊時會重疊命中（`"aaa".swapping("aa", with: "b")` 舊得 `"bb"`）；新實作採標準不重疊比對（得 `"ba"`，與 Foundation `replacingOccurrences` 一致）。全部既有呼叫端（拼音對照表、教科書格式表）的鍵皆無自體前後綴重疊，行為不變；新行為以測試鎖定。
- `cnvPhonaToHanyuPinyin`：查表改為「以首個 scalar 為鍵的對照桶（桶內按長度降冪）」，滑窗以 `elementsEqual` 純檢視比對，全程零配置；最長比對優先語意不變（同長度條目內容唯一，桶內順序無影響）。`_phonaToPinyinLUT` / `_maxPhonaPatternLength` 廢除。
- `cnvHanyuPinyinToPhona`：新增 `_sortedHanyuPinyinKeys` 預排序靜態鍵陣列（排序方式與舊逐次排序一致），不再每次呼叫排序。
- `isNotAllowedCharOfPinyinChain`：抽出 `Unicode.Scalar.isNotAllowedScalarOfPinyinChain`，兩變體改為單趟 `contains` 短路掃描。
- `restoreToneOneInPhona`：補空字串防呆（與 C# 版行為對齊；舊實作對空字串會在取末字時崩潰），聲調判定改為 `"ˊˇˋ˙".unicodeScalars.contains(lastScalar)` 零配置。

`Tekkon_SyllableComposer.swift`：

- `pinyinAutoChopResult` 的 `Array(chopped.dropLast())` 改為直接使用切片。

### 變更（TekkonNT，net46 / net6.0 相容）

`Shared.cs`：

- `CnvPhonaToHanyuPinyin`：同型對照桶（`Dictionary<char, List<KeyValuePair<string, string>>>`，桶內長度降冪），滑窗逐字元比對，廢除逐次 `Substring` 查表鍵；`PhonaToPinyinLUT` / `MaxPhonaPatternLength` 廢除。
- `CnvHanyuPinyinToPhona`：新增 `SortedHanyuPinyinKeys`（與舊 `OrderBy(x => x.Length).Reverse()` 完全同序）與 `ArayuruIntonationPairs`（預具體化字串形式，廢除逐次 `Rune.ToString()` 與 `new Rune('1')`）；字元白名單檢查由 `Regex.IsMatch` 改為 `Any(IsDisallowedPinyinChainChar)` 單趟掃描；移除 `System.Text.RegularExpressions` using。
- 刻意不用 tuple deconstruction / span API，維持 net46 相容。

### 變更（TekkonCC，C++17 header-only）

`Tekkon.hh`：

- `cnvPhonaToHanyuPinyin`：同型對照桶（`std::map<std::string, std::vector<std::pair<std::vector<std::string>, std::string>>>`，以首個 code point 為鍵、桶內長度降冪），滑窗逐 code point 比對，廢除逐位置逐長度拼裝的一次性 `std::string` 查表鍵；`_phonaToPinyinLUT` / `_maxPhonaPatternLength` 廢除。
- `cnvHanyuPinyinToPhona`：新增 `_sortedHanyuPinyinKeys` / `_sortedArayuruIntonationKeys` 預排序靜態鍵陣列（建構方式與舊逐次排序完全一致）；字元白名單檢查由 `std::regex` 改為 `isDisallowedPinyinChainChar` 單趟掃描；移除 `<regex>` include。
- `cnvHanyuPinyinToTextBookStyle`：迴圈改為 `const std::vector<std::string>&`，不再逐列拷貝對照表行。
- `replaceOccurrences` / `stringInclusion` / `contains`：by-value 參數改為 const 引用（行為不變、呼叫端零修改），廢除逐次呼叫的引數拷貝。
- `restoreToneOneInPhona`：補空字串防呆（舊實作對空字串會回傳 `"1"`，與 Swift / C# 版防呆行為對齊）。

`Tekkon.cc`：

- 移除函式庫 dummy translation unit 內無用的 `int main` stub——library target 不應定義 `main`，該 stub 導致 XCTest 套件與其重複 `_main` 符號而無法建置（GTests 執行檔有自己的 `GTests/main.cc`，不受影響）。移除後 `swift test` 的 XCTest 套件可正常建置執行。
